## 初始审查发现（历史快照，已由后续修复/增补复核）

以下条目保留原始审查证据，不能直接当作当前状态；当前是否仍成立，以本报告末尾“真实浏览器与 App 验收增补”为准。

### 1. 标准契约门禁失败（已修复）

`npm test` 发现错误码 golden 缺少：

- `invalid_key`
- `native_settings_reset_failed`
- `native_settings_write_failed`

对应路由已经发出这些错误码，但 [lib/contracts/fixtures/error-codes.json](/Users/cc/code/ompweb/lib/contracts/fixtures/error-codes.json:1) 没有同步更新。失败断言位于 [lib/contracts/agent-contract.test.mjs](/Users/cc/code/ompweb/lib/contracts/agent-contract.test.mjs:44)。

同一次测试还发现 motion manifest 记录了已经不存在的 `components/SubagentTreePanel.tsx`：[motion-manifest.json](/Users/cc/code/ompweb/docs/refactor/ompweb-5.0/baseline/motion-manifest.json:194)。

这两项必须明确更新 golden 后重跑完整测试，不能以“相关测试绿”替代标准门禁全绿。

### 2. 终端“新建”在同一 cwd 下不会新建（代码已修复，真实输入仍阻断）

`openTab()` 先按 cwd 复用已有 tab，[TerminalTabs.tsx](/Users/cc/code/ompweb/components/terminal/TerminalTabs.tsx:65)；`newTab()` 又无条件传入当前 cwd，[TerminalTabs.tsx](/Users/cc/code/ompweb/components/terminal/TerminalTabs.tsx:127)。

结果是：在同一项目目录点击 `+`，不会创建第二个 PTY/tab，只会重新激活已有 tab。快捷命令按 cwd 复用可以保留，但用户显式点击 `+` 必须支持强制新建。

### 3. 快捷命令可能重复执行（代码已修复，待真实快捷命令路径复测）

`terminalRunCommand` 保存在 AppShell 状态中且没有在消费后清空：[AppShell.tsx](/Users/cc/code/ompweb/components/AppShell.tsx:161)、[AppShell.tsx](/Users/cc/code/ompweb/components/AppShell.tsx:580)。

TerminalTabs 只在自身实例内用 `lastRunNonceRef` 去重：[TerminalTabs.tsx](/Users/cc/code/ompweb/components/terminal/TerminalTabs.tsx:97)。切换到 Files/Agents 后该子树可能重建，再切回 Terminal 时，旧 command 仍在父状态中，新实例会把它当作新命令重新执行。

应由父层或持久 nonce 记录确保每个快捷命令只投递一次。

### 4. 右栏关闭与 PTY 状态不一致（代码已统一，PTY 写入仍阻断）

顶部终端按钮在 Terminal 已激活时只把 `rightPanelOpen` 设为 `false`，不改变 `rightPanelTab`：[AppShell.tsx](/Users/cc/code/ompweb/components/AppShell.tsx:586)。但传给 TerminalTabs 的 `open` 只检查 `rightPanelTab === "terminal"`：[AppShell.tsx](/Users/cc/code/ompweb/components/AppShell.tsx:1869)。

因此可能出现“右栏已收起、TerminalTabs 仍认为 open、SSE/PTY 仍保持活动”的状态。

另外，TerminalTabs 的 `if (!open) return null`：[TerminalTabs.tsx](/Users/cc/code/ompweb/components/terminal/TerminalTabs.tsx:142)，会在切换到 Files/Agents 时卸载所有 TerminalPanel；这些 Panel 的 cleanup 会 reap PTY。也就是说代码注释声称的“panel-level keep-mounted”并未真正成立，切回 Terminal 可能得到新 shell，而不是原 tab 的持续 shell。

需要明确三种状态：活动显示、面板内隐藏但保活、真正关闭并 reap。

### 5. Provider 重命名存在配置覆盖风险（代码已增加守卫）

重命名校验只检查名称非空：[ModelsConfig.tsx](/Users/cc/code/ompweb/components/ModelsConfig.tsx:514)。实际重命名直接替换 providers 对象键：[ModelsConfig.tsx](/Users/cc/code/ompweb/components/ModelsConfig.tsx:1938)。

将 Provider A 改名为已存在的 Provider B 时，`Object.fromEntries()` 会产生重复键，后一个值覆盖前一个值，可能静默丢失 B 的配置。由于本轮新增 blur 自动提交，这条路径更容易被触发。

应在 blur、Rename 按钮和最终保存前统一拒绝目标键冲突，并补回归测试。

### 初始衔接风险（当前源码已加入对应缓解，仍需更多场景数据）

#### A. 深色主题下 splash 是硬编码暖白色（已修复）

`desktop/splash.html` 的 html、overlay、error panel 使用固定的 `#faf9f6`/`#2b2b2b`：[desktop/splash.html](/Users/cc/code/ompweb/desktop/splash.html:6)。RootLayout 则会在首帧从 localStorage 应用深色主题：[app/layout.tsx](/Users/cc/code/ompweb/app/layout.tsx:77)。

#### B. splash 没有遵循 reduced-motion / 应用动画开关（已修复）

应用 CSS 有 `prefers-reduced-motion` 和 `data-animations="false"` 总开关：[app/globals.css](/Users/cc/code/ompweb/app/globals.css:3031)。但 standalone `splash.html` 的视频、进度条动画和 body fade 没有对应媒体查询，也没有读取 `omp-motion-prefs`：[desktop/splash.html](/Users/cc/code/ompweb/desktop/splash.html:15)。

当前 `splash.html` 已读取 `omp-motion-prefs`，并通过 `prefers-reduced-motion` 停止进度条动画与过渡；视频本身仍应在 reduced-motion 场景做一次真实视觉复核。

#### C. 双层 fade 的真实视觉结果仍未验证

splash 自己先对 `body` 做 0.55 秒 fade，再跳转到 Next 页面；Next 页面随后还会显示 BootSkeleton，并在 session restoration 完成后再做约 170ms fade：[desktop/splash.html](/Users/cc/code/ompweb/desktop/splash.html:79)、[components/BootSkeleton.tsx](/Users/cc/code/ompweb/components/BootSkeleton.tsx:33)。

这种设计理论上能避免白屏，但也可能表现为：视频结束后等待时间过长、短暂重复显示 logo、或者在低速机器上出现“浅色 splash → skeleton → 深色应用”的两次过渡。必须通过真实 Electron 冷启动、禁用缓存启动、深色主题和 reduced-motion 四组场景确认。

## 性能与资源生命周期

### 已有缓解

- ChatWindow 的 ResizeObserver 通过 rAF 合并测量，避免每个 observer 回调都同步修改滚动位置。
- AgentsPanel 对计数、分组和排序使用 `useMemo`，减少无关渲染。
- TerminalPanel 对终端输入使用串行 promise chain，避免按键请求乱序。
- splash 预热请求有次数上限，服务器 readiness 有退避和最大尝试次数。

### 风险点

#### A. 右栏拖拽每个 pointermove 都写 localStorage

右栏宽度在每次 mousemove 中执行 state 更新和 `localStorage.setItem()`：[AppShell.tsx](/Users/cc/code/ompweb/components/AppShell.tsx:574)。设置导航宽度也通过 state effect 持久化：[SettingsConfig.tsx](/Users/cc/code/ompweb/components/SettingsConfig.tsx:369)。localStorage 是同步 API，低端设备或高频 pointermove 下可能造成拖拽掉帧。建议使用 rAF/内存更新，pointerup 时再持久化。

#### B. Settings dialog resize 同样在拖动过程中持续持久化

`useResizableDialog` 每次尺寸 state 改变都会写 storage：[useResizableDialog.ts](/Users/cc/code/ompweb/hooks/useResizableDialog.ts:49)。该问题不会阻塞功能，但与右栏拖拽叠加时会放大主线程同步工作。

#### C. 最多 8 个 TerminalPanel 会保留大量前端/后端资源

TerminalTabs 允许 8 个 tab：[TerminalTabs.tsx](/Users/cc/code/ompweb/components/terminal/TerminalTabs.tsx:15)。每个 tab 都对应 xterm 实例，且设计上 PTY 可在后台保留 30 分钟。若用户频繁开关面板或同时打开多个 tab，内存、PTY 数量和恢复流量都会上升；应通过真实长时间运行与 8-tab 压测确认 12 PTY 后端预算不会被耗尽。

#### D. Agents 高频 SSE 仍会创建新数组并重新排序

代码注释说明 progress 约 10Hz；即使 `useMemo` 避免了无关依赖，每次新 roster 引用仍会重做分组、排序和所有 live card render。普通数量下可接受，但需要在 20+ subagents、长任务和低端机器上测量。

#### E. splash 预热最多并发请求 40 个资源

`assets.slice(0, 40)` 后直接发起多个 fetch：[desktop/splash.html](/Users/cc/code/ompweb/desktop/splash.html:181)。这能减少首屏空白，但在冷磁盘、杀毒软件扫描或低带宽环境中可能与主页面导航争用连接和 CPU。应在 packaged 冷启动日志中验证收益，而不是只凭 dev server 200 判断。
