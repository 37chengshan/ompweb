# OmpWeb 稳定性收尾与下一轮验收计划

日期：2026-09-05。审查基线：`4688a4c`，基线版本 `5.1.7`，本次发布候选 `5.1.9`。

本轮范围由“深度审查与迭代文档”收敛为“顺手修复、先不加新功能”。本文档只安排缺陷修复、集成验证和发布准备，不增加产品功能、不改变技术栈。用户确认另一任务也在修改同一工作区；本轮保留其改动并进行集成复核，未使用子代理。

## 结论

原始基线存在 npm 缺失 Rust host、配对门禁组合错误、Rust 重启后旧 stdin、全局锁覆盖阻塞 I/O、命令超时后管道等待等确定问题。源码已经修复，并补充故障回归；实际产物验证还发现并修复了授权目录别名与真实路径不一致导致终端创建失败的问题。

用户随后授权“继续，然后推送发布”，本轮已进入 5.1.9 发布流程。实际状态以 [发布记录](06-release.md) 为准；构建与基础安装冒烟不代表 Windows/App/移动端所有场景均已验收。 各环境的证据边界和最终测试数字以 [验证记录](04-verification.md) 为准。

## 下一轮顺序

1. **先固定候选提交和产物。** 等同一工作区的并行修改完成，将本轮最终差异统一审查；全绿后再确定版本。不能用不同 HEAD 的测试结果拼成“全绿”。
2. **复现 npm 四平台安装。** CI 构建并聚合 Linux x64、macOS arm64/x64、Windows x64 host；从最终 `.tgz` 安装，而非从源码目录启动。
3. **执行独立的 Windows 和 packaged App 验收。** 用户可见的启动、路径、终端和退出必须在目标程序里操作。Web 通过不能替代 App 通过。
4. **执行移动端/弱网与资源稳定性验收。** 聚焦已有功能：键盘、安全区域、目录刷新、SSE 断线、长会话；不插入新 UI 或新架构。
5. **满足发布门禁后发布。** 用户已授权推送与发布；发布动作和验证结果单独写入 [发布记录](06-release.md)。

## 统一完成标准

- 高优先级缺陷必须有“触发条件 → 修复 → 行为回归”证据。
- 默认 Rust 路径与显式 Node 回滚路径分别标注；不以回滚可用冒充 Rust 已修复。
- 正常路径与失败路径同时验证：本机可访问且伪造 Host 被拒绝；重启后能继续通信且用户取消不会复活；超时返回且进程可回收。
- 新增回归已经接入现有测试 glob。未执行的目标环境保留明确的待验收状态。
